# Railway SSH Server

A lightweight SSH server that can be deployed on **Railway** using a GitHub repository.

The server provides a standard SSH connection and has been successfully tested with **NekoBox** as an SSH-based tunnel.

> **Tested successfully:** Railway + SSH + TCP Proxy + NekoBox

---

## Features

* Lightweight OpenSSH server
* Easy deployment on Railway
* Username/password authentication
* Railway TCP Proxy support
* Successfully tested with NekoBox
* No external VPS required

---

# 1. Deploy to Railway

Create a new project on Railway and deploy this GitHub repository.

After deployment, wait for the container to start.

A successful deployment should show logs similar to:

```text
Generating SSH host keys...
Creating SSH user: sshuser
Starting OpenSSH server...
Listening on 0.0.0.0:2222
Server listening on 0.0.0.0 port 2222.
```

If you see:

```text
Server listening on 0.0.0.0 port 2222.
```

the SSH server is running correctly inside the Railway container.

---

# 2. Configure Railway Variables

Go to:

**Railway → Service → Variables**

Create only these two variables:

| Variable   | Example value        | Description  |
| ---------- | -------------------- | ------------ |
| `USERNAME` | `sshuser`            | SSH username |
| `PASSWORD` | `YourStrongPassword` | SSH password |

Example:

```env
USERNAME=sshuser
PASSWORD=YourStrongPassword
```

### Important

**You do NOT need to create a `PORT` variable.**

The project automatically uses **port `2222`** for the SSH server.

Use your own username and a strong password.

The password should never be committed to GitHub.

---

# 3. Create a TCP Proxy

## This step is REQUIRED

Adding `USERNAME` and `PASSWORD` is **not enough** to access the SSH server from the Internet.

Railway must expose the internal SSH port through a **TCP Proxy**.

Go to:

**Railway → Service → Settings → Networking**

Create a **TCP Proxy** for the internal port:

```text
2222
```

Railway will generate an external hostname and port.

For example:

```text
altaria.proxy.rlwy.net:11641 → 2222
```

The hostname and external port are generated by Railway and may be different for each service.

---

# 4. Understanding the Port Mapping

The Railway configuration looks like this:

```text
Internet
   │
   ▼
altaria.proxy.rlwy.net:11641
   │
   │ Railway TCP Proxy
   ▼
Container:2222
   │
   ▼
OpenSSH Server
```

In this example:

```text
Public Host: altaria.proxy.rlwy.net
Public Port: 11641

Internal SSH Port: 2222
```

### Important

Do **not** use `2222` as the public port in your SSH client.

`2222` is the **internal SSH port inside the Railway container**.

Your SSH client must use the **external port generated by Railway**.

---

# 5. Connect to the SSH Server

Using the example TCP Proxy:

```text
Host: altaria.proxy.rlwy.net
Port: 11641
Username: sshuser
Password: YourStrongPassword
```

Replace these values with your own Railway configuration.

---

# 6. NekoBox

The project has been successfully tested with **NekoBox**.

Use your Railway TCP Proxy information as the SSH server.

Example:

```text
SSH Host: altaria.proxy.rlwy.net
SSH Port: 11641
Username: sshuser
Password: YourStrongPassword
```

The important part is that:

```text
altaria.proxy.rlwy.net:11641
```

comes from the Railway TCP Proxy.

Do not use:

```text
altaria.proxy.rlwy.net:2222
```

because `2222` is the internal container port.

# 9. Quick Setup

The complete setup is:

```text
1. Deploy the repository to Railway
2. Add USERNAME
3. Add PASSWORD
4. Redeploy the service
5. Open Settings → Networking
6. Create a TCP Proxy for port 2222
7. Copy the hostname and external port generated by Railway
8. Configure NekoBox using the TCP Proxy hostname and port
9. Use the same USERNAME and PASSWORD
```

### Example

Railway Variables:

```env
USERNAME=sshuser
PASSWORD=YourStrongPassword
```

Railway Networking:

```text
altaria.proxy.rlwy.net:11641 → 2222
```

NekoBox:

```text
Host: altaria.proxy.rlwy.net
Port: 11641
Username: sshuser
Password: YourStrongPassword
```

That's it. 🚀

# Security Notice

This project exposes an SSH service to the Internet through Railway TCP Proxy.

For better security:

* Use a strong and unique password.
* Never commit your password to GitHub.
* Do not share your SSH credentials.
* Change your password if it has been exposed.
* Keep the project and dependencies updated.
* Use the server only for lawful purposes.
